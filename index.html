Sintaxis que debes reconocer antes de Angular

No necesitas memorizarla. La meta es que cuando la veas, sepas qué está intentando decir el código.

Regla para principiantes: no intentes leer una línea completa de golpe. Divídela en piezas pequeñas: variable, tipo, función, parámetro y resultado.

1. Símbolos que vas a encontrar todo el tiempo

Diccionario visual de símbolos

El mismo símbolo puede cambiar de significado según el contexto.

chuleta rápida
()Paréntesis

Llaman una función: guardar(). También contienen parámetros: eliminar(id).

[]Corchetes

En TypeScript crean arrays: Estudiante[]. En templates Angular hacen property binding: [disabled].

{}Llaves

Crean objetos o delimitan bloques de código. Ejemplo: { nombre: 'Ana' }.

<>Genéricos

Indican el tipo con el que trabaja algo: signal<Estudiante[]>.

Es una función corta. Ejemplo: x => x.id.

...Spread

Copia elementos o propiedades: [...actuales, nuevo].

Accede a algo que pertenece a un objeto: estudiante.nombre.

:Dos puntos

En TypeScript separa nombre y tipo: id: number.

?Interrogación

Puede significar “opcional” en externo?: boolean o formar parte de un ternario.

@Angular

Lo verás en @Component, @if y @for. No todos significan exactamente lo mismo.

Ejemplo: #form="ngForm". Crea un nombre local dentro del HTML.

$eventDato del evento

Angular coloca aquí el valor que produjo un evento: eliminar($event).

2. Aprende a desarmar una línea difícil

private readonly _estudiantes = signal<Estudiante[]>([]);
private
Solo la clase del servicio puede acceder directamente a esta propiedad.
readonly
No podremos hacer otra asignación como _estudiantes = otraCosa. El Signal sí puede cambiar internamente con set() o update().
_estudiantes
Es el nombre de la propiedad. El guion bajo es una convención para indicar que es interna.
=
Asigna a la propiedad el resultado de lo que está a la derecha.
signal
Función de Angular que crea estado reactivo.
<Estudiante[]>
Le dice a TypeScript: “este Signal guardará un array de estudiantes”.
([])
Valor inicial: un array vacío.
No leas: “private readonly underscore estudiantes igual signal menor que…”. Lee la intención: “Creo una lista privada y reactiva de estudiantes, inicialmente vacía”.

() =>
Función sin parámetros que indica cómo calcular el valor.
this.estudiantes()
Leo el Signal de estudiantes.
.filter(...)
Creo una lista nueva conservando solo algunos elementos.
e =>

e.semestre > 2
Solo conserva estudiantes con semestre mayor que 2.

JavaScript normal vs Angular

Angular no elimina JavaScript: cambia la forma de conectar estado e interfaz.

1. Mostrar un dato

JavaScript
titulo.textContent = nombre;
Angular HTML
<h1>{{ nombre }}</h1>

En Angular describes el resultado; no buscas manualmente el elemento.

2. Escuchar un clic

JavaScript
boton.addEventListener(
  'click',
  guardar
);
Angular HTML
<button (click)="guardar()">
  Guardar
</button>

El evento se declara directamente en el template.

3. Mostrar/ocultar contenido

JavaScript
mensaje.style.display =
  visible ? 'block' : 'none';
Angular HTML
@if (visible) {
  <p>Mensaje</p>
}

Angular decide si el bloque existe en el DOM.

4. Estado reactivo

JavaScript
let total = 0;
total++;
actualizarPantalla();
Angular / Signals
total = signal(0);
total.update(n => n + 1);

Las dependencias del Signal pueden reaccionar automáticamente.

Idea central: en JavaScript tradicional sueles decir “busca este elemento y cámbialo”. En Angular describes “esta vista depende de este estado”.

La idea más importante de toda esta sección: cuando un dato importante cambia, no queremos recorrer manualmente toda la aplicación diciendo “actualízate tú, actualízate tú y actualízate tú”. Queremos que las partes interesadas reaccionen porque dependen de ese dato.

1. Antes de Observer: entiende el problema

Imagina que Angular Aula tiene tres lugares que muestran información relacionada con estudiantes: el listado, el Dashboard y un contador en la cabecera. Los tres dependen de la misma lista.

Si mañana agregamos otra pantalla, tenemos que recordar actualizarla también. El código que cambia el dato empieza a conocer demasiadas partes de la aplicación.
Observer intenta romper esa dependencia manual. La fuente del dato cambia una sola vez y las partes que dependen de ella reaccionan.

2. ¿Qué es un patrón de diseño?

No es código para copiar

Un patrón de diseño es una idea de organización que se ha usado muchas veces para resolver un tipo de problema frecuente.

No es una librería

No instalamos npm install observer. El patrón describe cómo repartir responsabilidades.

Problema repetido

“Varias partes necesitan enterarse cuando cambia un dato”.

4. Los participantes del patrón Observer

1. Sujeto / fuente El dato que puede cambiar y que otros necesitan conocer.
2. Observadores Partes interesadas en reaccionar cuando cambia la fuente.
3. Cambio Una operación modifica el estado observado.
4. Reacción Los observadores recalculan o actualizan lo que muestran.

17. Lo que Observer NO significa

No significa “todo global”

No todos los datos de la aplicación necesitan vivir en el mismo servicio.

No significa “sin métodos”

Seguimos usando agregar(), eliminar() y reglas de negocio.

No significa “Signal = patrón”

Signal es una herramienta reactiva; Observer es la idea de dependencias que reaccionan al cambio.

18. Errores comunes al aplicarlo

Error 1 · Exponer el Signal modificable
Si cualquier componente puede llamar set() o update(), el servicio deja de controlar cómo cambia el estado. Usa asReadonly() cuando quieras exponer lectura.
Error 2 · Crear dos listas diferentes
Si Inicio tiene su propio array y Estudiantes otro diferente, ya no existe una fuente única. Ambas pantallas pueden terminar mostrando información distinta.
Error 3 · Calcular el total manualmente
Guardar total como otro estado independiente obliga a mantenerlo sincronizado. Si el total depende completamente de la lista, es mejor derivarlo con computed().

Entiende qué hace ng build

El servidor de desarrollo no es la versión que se publica. El build genera archivos optimizados para producción.

ng serve
Compila para desarrollo, inicia servidor local y observa cambios.
ng build
Compila y optimiza la aplicación para distribución.
dist/
Carpeta de salida donde Angular deja los archivos construidos.
sin errores
Antes de entregar, el build debe finalizar correctamente; así detectas problemas que podrían pasar desapercibidos.
Qué debes recordar: durante el curso usa ng serve; antes de entregar ejecuta ng build.

Entrega final

No marques esta etapa hasta que ng build finalice correctamente y hayas probado toda la checklist.

Qué revisar primero cuando algo falla.

ErrorQué revisar

ngModel desconocidoImporta FormsModule.
routerLink desconocidoImporta RouterLink.
Componente desconocidoAgrega el componente al array imports.
Template no actualizaSi usas Signal, lee con () y modifica con set/update.
Datos desaparecenVerifica llamadas a guardar().
Página en blancoLee primero la terminal de ng serve y luego Console del navegador.

Proyecto guiado · Gestor de tareas
