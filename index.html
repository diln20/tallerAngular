Entiende el componente raíz

Este bloque conecta una clase TypeScript con un archivo HTML y un archivo CSS.

import { Component }
Trae Component desde Angular. Sin este import, TypeScript no sabría qué significa @Component.
@Component({...})
Es un decorador. Le entrega a Angular información sobre la clase que aparece debajo.
selector: 'app-root'
Define la etiqueta que representa este componente. Angular monta este componente como raíz de la aplicación.
imports: []
Lista lo que el template puede utilizar. Más adelante aquí aparecerán RouterLink, RouterOutlet u otros componentes.
templateUrl: './app.html'
Le dice a Angular: «la parte visual de este componente está en app.html».
styleUrl: './app.css'
Conecta los estilos propios del componente. No son los estilos globales de toda la aplicación.
export class App {}
Es la clase TypeScript del componente. Aquí irán variables, Signals y métodos que el template necesite.
Qué debes recordar: un componente Angular normalmente tiene lógica (TS), vista (HTML) y estilos (CSS).

6

Signals: manejar estado reactivo

Pasamos de variables simples a estado que Angular puede observar.

src/app/app.ts
app.ts 
import { Component, computed, signal } from '@angular/core';

@Component({
  selector: 'app-root',
  imports: [],
  templateUrl: './app.html',
  styleUrl: './app.css'
})
export class App {
  estudiantes = signal(['Ana', 'Carlos']);

  total = computed(() => this.estudiantes().length);

  agregarTemporal(): void {
    this.estudiantes.update(actuales => [
      ...actuales,
      'Laura'
    ]);
  }
}
src/app/app.html
app.html 
<p>Total: {{ total() }}</p>

<button type="button" (click)="agregarTemporal()">
  Agregar Laura
</button>
signal(valor)
Crea estado reactivo.
signal()
Lee el valor actual.
update()
Calcula el nuevo valor usando el anterior.
computed()
Calcula un valor derivado.
💡
Entiende Signals sin complicaciones

Un Signal guarda un valor y avisa a Angular cuando ese valor cambia.

signal(['Ana', 'Carlos'])
Crea un estado reactivo. Aquí el valor inicial es un array con dos nombres.
this.estudiantes()
Los paréntesis sirven para leer el valor actual de un Signal.
update(actuales => ...)
Actualiza el Signal usando su valor anterior. actuales representa el array que existe en ese momento.
...actuales
El operador spread copia los elementos existentes a un nuevo array.
computed(() => ...)
Crea un valor calculado a partir de otros Signals. Si cambia estudiantes, total se recalcula.
this.estudiantes().length
Lee el array y obtiene cuántos elementos contiene.
Qué debes recordar: Signal = estado; computed() = valor que depende de ese estado.

Control de flujo con @if y @for

Mostramos listas y estados directamente desde el template.

src/app/app.html
app.html 
<h2>Estudiantes</h2>

@if (total() > 0) {
  <p>Hay {{ total() }} estudiantes.</p>
} @else {
  <p>No hay estudiantes.</p>
}

@for (nombre of estudiantes(); track nombre) {
  <article class="panel">
    {{ nombre }}
  </article>
} @empty {
  <p>La lista está vacía.</p>
}
@if: decide si una parte del HTML existe. @for: repite una parte del template por cada elemento.
💡
Entiende @if, @for y @empty

Estas instrucciones controlan qué HTML crea Angular.

@if (total() > 0)
Solo crea el bloque si la condición es verdadera.
@else
Se utiliza cuando la condición anterior es falsa.
@for (nombre of estudiantes(); ...)
Recorre la colección. En cada vuelta, nombre representa un elemento.
track nombre
Ayuda a Angular a identificar cada elemento y actualizar solo lo necesario.
@empty
Se muestra cuando la colección del @for está vacía.
Qué debes recordar: no necesitas crear HTML manualmente con innerHTML; Angular lo genera a partir del estado.

import { computed, Injectable, signal } from '@angular/core';
import { Estudiante } from '../models/estudiante';

@Injectable({
  providedIn: 'root'
})
export class Estudiantes {
  private readonly _estudiantes = signal<Estudiante[]>([
    {
      id: 1,
      nombre: 'Ana Torres',
      email: 'ana@correo.com',
      programa: 'Ingeniería de Sistemas',
      semestre: 4
    },
    {
      id: 2,
      nombre: 'Carlos Ruiz',
      email: 'carlos@correo.com',
      programa: 'Diseño',
      semestre: 2
    }
  ]);

  readonly estudiantes = this._estudiantes.asReadonly();
  readonly total = computed(() => this._estudiantes().length);

  agregar(datos: Omit<Estudiante, 'id'>): void {
    const nuevo: Estudiante = {
      id: Date.now(),
      ...datos
    };

    this._estudiantes.update(actuales => [
      ...actuales,
      nuevo
    ]);
  }

  eliminar(id: number): void {
    this._estudiantes.update(actuales =>
      actuales.filter(estudiante => estudiante.id !== id)
    );
  }
}

importarDesdeApi() {
  return this.http
    .get<UsuarioApi[]>(
      'https://jsonplaceholder.typicode.com/users'
    )
    .pipe(
      tap(usuarios => {
        const nuevos: Estudiante[] =
          usuarios.slice(0, 5).map(usuario => ({
            id: Date.now() + usuario.id,
            nombre: usuario.name,
            email: usuario.email,
            programa: 'Importado desde API',
            semestre: 1,
            externo: true
          }));

        this.agregarVarios(nuevos);
      })
    );
}

cargando = signal(false);
mensaje = signal('');

importar(): void {
  this.cargando.set(true);
  this.mensaje.set('');

  this.servicio.importarDesdeApi().subscribe({
    next: () => {
      this.cargando.set(false);
      this.mensaje.set(

      );
    },
    error: () => {

}

Entiende subscribe(), carga y error

Una petición tarda y puede fallar. La interfaz debe representar esos estados.

cargando = signal(false)
Indica si hay una petición en curso.
mensaje = signal('')
Guarda un mensaje de éxito o error para el usuario.
subscribe({...})
Activa la suscripción al Observable y define qué hacer con sus resultados.
next: () => {...}
Se ejecuta cuando la operación termina correctamente.
error: () => {...}
Se ejecuta si la petición falla.
[disabled]="cargando()"
Evita presionar el botón varias veces mientras la petición sigue activa.
cargando() ? 'Importando...' : ...
Operador ternario: escoge uno de dos textos según una condición.
@if (mensaje())
Muestra el mensaje solo cuando el Signal contiene texto.
Qué debes recordar: toda operación remota debería considerar al menos: cargando, éxito y error.
